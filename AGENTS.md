# AGENTS.md — Cartographer

Go MCP server for the *Agentic Wiki* (Karpathy pattern + OKF). The agent never touches files directly: it operates via MCP tools; the server enforces the invariants. → `docs/overview.md`

## Commands

```
make gate            # gofmt + vet + test + race: everything green before a PR (and what CI runs)
make check           # fast tier (affected packages only)
make signoff         # maintainer: gate, push, attest the sha (CI's gate)
make build           # → bin/cartographer
make test            # go test ./...
make vet             # go vet ./..., also GOOS=windows
make fmt             # gofmt -w cmd internal
make run             # stdio with demo KB
make run-http        # HTTP on :39273 with demo KB
make smoke           # build + quick stdio test
make smoke-http      # HTTP smoke test (temp KBs via curl)
make e2e             # HTTP/CLI end-to-end scenarios
make test-install    # install.sh/Cask packaging suite + goreleaser guard
make docker          # build Docker image

make ready MSG=<file>              # maintainer: queue the change, the lander lands it
make decisions-new SLUG=my-choice TOPIC=control-plane   # D-new-<slug>, numbered on landing
make decisions-index # regenerate docs/decisions.md locally (the release PR does it, D328)
make worktree-add SLUG=my-change   # isolated worktree for a plan branch
make worktree-rm  SLUG=my-change   # remove it (force: discards uncommitted work)
make worktree-clean [DRY=1]        # remove worktrees of merged PRs and landed trains, each checked
make dev [DATA=<data dir>]         # live instance: Go rebuilt on change, UI hot-reloaded
```

```bash
./bin/cartographer serve --kb /path/to/kb             # local stdio server (the KB exists: `kb create`)
./bin/cartographer serve --config config.yaml         # HTTP/stdio server (YAML, see config.example.yaml)
./bin/cartographer connect|disconnect|status|sync     # multi-provider client (HTTP)
./bin/cartographer                                    # TUI dashboard (if TTY), otherwise usage
```

Protocol: JSON-RPC 2.0. Stdio = newline-delimited. HTTP = POST /mcp. Logs on stderr.

## Rules that apply everywhere

Structural questions about the code (where does X live, who calls Y) are answered with targeted Grep/Explore, then reading only the indicated `file:line` locations.

- the **why** lives in `docs/decisions/`, one file per decision (`ls docs/decisions/D47-*`), current behavior in `docs/` (map in `docs/index.md`);
- mandates to a coding subagent include the `file:line` pointers already derived.

## Areas

Two areas carry invariants you cannot derive from the code, each with its own `AGENTS.md`
and a one-line `CLAUDE.md` import (D213). Read it before editing there: Claude Code loads it
on its first read of a file in that directory, other clients only if launched at or below it:

- `internal/mcpserver/AGENTS.md` — how to add a tool, and the three things about
  scopes, locking and commits that a handler must not do itself.
- `internal/provisioning/AGENTS.md` — this package writes into other people's home
  directories; a defect there does not fail a test, it modifies files silently.

## Working rules

- All changes land via PR: `main` is protected (required `gate`, `pr-title`, `plan-gate`). A contributor's PR is squash-merged; a maintainer's change is queued (`make ready`) and lands in a train (`CONTRIBUTING.md` §Pull requests). Titles are conventional commits: release-please computes the semver bump from them.
- **Route a maintainer's change before writing any code**: a bug → an `accepted` `bug` issue with the design in a comment, fixed by `cartographer-fix-implementer` (`CONTRIBUTING.md` §Fixes without a plan); a feature → a plan (`cartographer-propose-plan`) implemented by `cartographer-implement-plan`; a change found by trying it → a live session (below). The coordinator writes no production code itself: it reviews and queues.
- **This repository is public**: before any commit, doc, test, issue, PR or comment, replace what came from a real setup — KB names → `kb-a`/`work-kb`, hosts → `example.com`/`gitlab.example.com`, users → `user`, paths → `$HOME/…` — and drop employer, client and project names; in doubt, a name is private. The `privacy` workflow is a net, not the filter (D259).
- **Done** means: `make check` green; the docs named in `docs/index.md` §Documentation maintenance rules updated in the same session; every trap you hit fixed where it bites — a test if it can be checked, a comment next to the code, otherwise one line in the area `AGENTS.md` or the procedure's skill (D214); one decision file per architectural or contract choice (D672).
- Design and implementation often happen in separate sessions: the maintainer's handoff is a **plan file** kept outside the repository (`CONTRIBUTING.md` §Plans): no agent implements a plan the maintainer did not give it in the session. A contributor opens an issue or a direct PR.
- **Roles are GitHub permissions** (D955): `WRITE`/`MAINTAIN`/`ADMIN` on upstream is a maintainer, anyone else a contributor whose agent stops at an open PR (`CONTRIBUTING.md` §Working with an agent client).
- A change whose outcome is found by trying it (Atlas UI, UX, output to tune) needs no plan: it is a **live session** with the user, ending in one queued change (`cartographer-develop-live` skill).
- A PR, or a change before `make ready`, is reviewed with the `cartographer-review-pr` skill: scripted triage, then the `cartographer-contract-reviewer` subagent; the coordinator verifies only the lines its findings cite. Size cap: `CONTRIBUTING.md` §Pull requests.
- Releases (release-please PR merge, pipeline, rollout) → maintainer-local tooling, not versioned here; the on-demand flow is in `CONTRIBUTING.md` §Releases.
- **Documentation is updated in the same session as the code — never afterward.** The "what changes → which file" table is in `docs/index.md` §Documentation maintenance rules.
- Conventions → `docs/conventions.md`. A decision is `docs/decisions/D<n>-<slug>.md`, `<n>` the PR's (D672) or, queued, `D-new-<slug>` numbered by the lander; never regenerate `docs/decisions.md` in a feature PR (D328).
- **This file is stable imprinting**: no mutable state, versions, counts or changelog. Topic docs describe the **current state**; "how we got here" lives in `docs/decisions/` and the git log. Its size is a gate — `internal/repodocs` fails the build past 120 hand-written lines (generated blocks excluded) or 12.000 characters in total: past that a client drops instructions silently.
