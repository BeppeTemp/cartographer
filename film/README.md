# Launch film (draft)

A ~46 s silent motion-graphics film. The graph is the real Atlas engine (`LivingScene`, offscreen); the page is a pure
function of time, so it renders deterministically. Nothing under `web/` is touched (it would change the bundle hash).

1. Preview (plays in real time, loops, `R` restarts): `cd web && npx vite --config ../film/vite.config.ts`, open http://localhost:5180/
2. Keep that server running, then in another shell from the repo root:
3. Review stills: `node film/record.mjs --stills 2.5,6,9,11,17,27,31,37,45` writes `film/out/still-<s>.png` (fractional seconds allowed)
4. Full render, headless, with no server to start (what CI runs, with `--no-mp4`; `--frames N` renders only the first N frames and skips the frame-count check, as `film-check.yml` does on a pull request): `film/render.sh` starts the server, runs `node film/record.mjs`, stops the server and fails when `film/out/film.webp` is missing. Or by hand, `node film/record.mjs` writes `film/out/frames/*.png`, (emptied first) then `film/out/film.mp4` and `film/out/film.webp`: one command does it all (needs ffmpeg for the mp4 and `img2webp`, from Homebrew's `webp` package, for the animated WebP: ffmpeg has no libwebp encoder there)
5. Frames must be rendered in order from 0 (the physics is stateful); the script does, and `--stills` still renders all frames up to the last still.
6. WebGL in headless Chromium goes through SwiftShader (software), so a full render takes minutes, not seconds.
7. Everything is in `film/src/main.ts` (timeline in `overlays()` and `EVENTS`; the cast, one person per coding agent and colour, is `CAST`; scenes A team, B one wiki, C Monday, D Tuesday, E every day, F end card); the synthetic KB is `film/src/data.ts`.
8. `film/out/` is git-ignored.
9. **CI (D1068).** The release candidate (`preview.yml`, job `film`, `film.yml`) renders the film with `film/render.sh --no-mp4` and `film/publish.sh` force-pushes it as the one commit of `readme-film`, which the README embeds. It does so only when the hash of the film's inputs (`film/inputs.sh`: this directory, `web/src/lib/graph3d/`, the palette and theme modules, the tokens, the brand CSS and logo, `web/package-lock.json`) differs from the `Film-Tree:` trailer of that commit (`film/film-needed.sh <rev>`: exit 0 render, 1 not needed, 2 bad usage or revision or a missing input, 3 origin unreachable). A page error or a frame count that is not the film's makes `record.mjs` exit non-zero, and a failed render fails the candidate and so the release train. A file reached from `film/` through imports, however indirectly, goes in `film/inputs.sh` (a test follows them transitively). The workflow has two jobs: `render` is read-only (`contents: read`, no credential left in `.git/config`) and uploads the film as an artifact; `publish` holds `contents: write`, only downloads it and runs `film/publish.sh`, and only on `main` (a manual run of another ref renders it, to check, and does not publish). The candidate is built from the head of `main` and the Monday train requires that head, so the released film is always rendered from the released sources. A manual run always renders: `gh workflow run film.yml`. To publish by hand, `film/publish.sh` from the repository root after a render.
