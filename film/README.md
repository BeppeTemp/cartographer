# README films (draft)

The README films are a set: `film/films.txt` lists them, one name per line, and it is the one list `render.sh`, `record.mjs` and `vite.config.ts` read. `launch` (the README's video, page `index.html`, file `film.webp`), `plugins` (page `plugins.html`, script `src/plugins.ts`, file `plugins.webp`) and `deployment` (page `deployment.html`, script `src/deployment.ts`, file `deployment.webp`). A film is a page `film/<name>.html` (the launch film's is `index.html`) loading `film/src/<name>.ts` (the launch film's is `main.ts`), which imports the shared kit and CSS and ends with `defineFilm({fps, duration, frame})`. Adding a film is one line in `films.txt`, its page and its script; `TestFilmPagesAreTheFilmList` (`internal/repodocs`) fails when the list and the pages disagree.

- `film/src/kit.ts`: what every film shares: the stage (1920x1080) and its scaling, the easing helpers, `mk`/`vis`/`reveal`/`fade`, and `defineFilm()`, which installs `window.film` `{fps, frames, frame, rendered}` for `record.mjs` (it refuses a frame out of order, waits for the fonts before frame 0) and runs the real-time preview loop without `?record`.
- `film/film.css`: the page CSS (stage, cards, terminal, end card); each film script imports it first.

## The launch film

A ~82 s silent motion-graphics film (the team, one shared wiki, and the four components). The graph is the real Atlas engine (`LivingScene`, offscreen); the page is a pure
function of time, so it renders deterministically. Nothing under `web/` is touched (it would change the bundle hash).

1. Preview (plays in real time, loops, `R` restarts): `cd web && npx vite --config ../film/vite.config.ts`, open http://localhost:5180/ (the launch film) or http://localhost:5180/<name>.html (another film)
2. Keep that server running, then in another shell from the repo root:
3. Review stills: `node film/record.mjs --stills 2.5,6,9,11,17,27,31,37,52,58,63.5,68.5,74,80` (the last five are inside scene G and the end card) writes `film/out/still-<s>.png` (fractional seconds allowed); `--film <name>` (default `launch`) picks the film, and another film's stills are `film/out/still-<name>-<s>.png`
4. Full render, headless, with no server to start (what CI runs, with `--no-mp4`; `--frames N` renders only the first N frames and skips the frame-count check, as `film-check.yml` does on a pull request): `film/render.sh [--films a,b] [record.mjs options]` starts the server once, renders each film (all of `films.txt` by default), stops the server and fails when a film's `.webp` is missing. Or by hand, `node film/record.mjs --film <name>` writes `film/out/frames-<name>/*.png` (emptied first) then `film/out/<file>.mp4` and `film/out/<file>.webp`, where `<file>` is `film` for the launch film (the name the README embeds) and the film's name for the others: one command does it all (needs ffmpeg for the mp4 and `img2webp`, from Homebrew's `webp` package, for the animated WebP: ffmpeg has no libwebp encoder there)
   - **Size cap per file.** The README must not grow without limit: the caps are the lines of `film/max-bytes.txt` (`<film> <bytes>`; `default` is 8388608, 8 MiB, for a new film; `launch` is 25165824, 24 MiB: the film was about 20 MB at 60 s and is estimated at about 27 MB at 82 s with q85, so it is encoded at q80 to fit; the first render measures it), the one source of both checks: `record.mjs` exits 1, naming the file and both sizes, when a WebP is over its film's cap, and `film/publish.sh` checks again before it hashes or pushes anything (the render job runs code of an untrusted ref, the publish job holds the write token), exit 1 naming the file, its size and the cap. A line is the film and its bytes split by spaces or tabs (a trailing CR is dropped, `#` and blank lines are skipped), and bytes is 1 to 15 digits with no leading zero, in the file and in `FILM_MAX_BYTES`; the three parsers (`record.mjs`, `publish.sh`, `TestFilmCapGrammar`) share that grammar, so a no-break space or a vertical tab as separator, a 16-digit value, or a NUL byte anywhere in the file, is the same error in each. `FILM_MAX_BYTES` overrides the cap of every film of that run, in either script. A new film with a heavier story gets a line in the file. A heavy story fails the render, which blocks the release candidate, not a reader's browser: shorten the film, or lower the WebP quality (`LAUNCH_QUALITY` 80 for the launch film, `DEFAULT_QUALITY` 85 for the others, in `record.mjs`, passed as `-q` to `img2webp`) before cutting a scene.
5. Frames must be rendered in order from 0 (the physics is stateful); the script does, and `--stills` still renders all frames up to the last still.
6. WebGL in headless Chromium goes through SwiftShader (software), so a full render takes minutes, not seconds.
7. The launch film is all in `film/src/main.ts` (timeline in `overlays()` and `EVENTS`; the cast, one person per coding agent and colour, is `CAST`; scenes A team, B one wiki, C Monday, D Tuesday, E every day, G the four components, F end card). Scene G (story seconds 40 to 62, film seconds 53.4 to 75.4: `WARP` plays it 1:1) lights one component per 5 s and dims it when the next lights, in the order the docs name them (D1867): Meridian (a frame and a lock around the graph), the Surveyor (a card outside the frame, a dotted line to a clay-bordered note it adds), the Atlas (a browser window over the graph), Compass (a tag on each laptop's line). Its texts must stay true to `docs/deployment.md` §Components; the end card starts at `EC` in `main.ts`; the synthetic KB is `film/src/data.ts`.
8. `film/out/` is git-ignored.
9. **CI (D1068).** The release candidate (`preview.yml`, job `film`, `film.yml`) renders the films with `film/render.sh --no-mp4` and `film/publish.sh` force-pushes them (the file of each film of `films.txt`, under its own file name: any other `film/out/*.webp`, or a symlink, is refused) as the one commit of `readme-film`, which the README embeds. It does so only when the hash of the films' inputs (one hash for the whole set: all of `film/` is an input, so a change to any film renders them all) (`film/inputs.sh`: this directory, `web/src/lib/graph3d/`, the palette and theme modules, the tokens, the brand CSS and logo, `web/package-lock.json`) differs from the `Film-Tree:` trailer of that commit (`film/film-needed.sh <rev>`: exit 0 render, 1 not needed, 2 bad usage or revision or a missing input, 3 origin unreachable). A page error or a frame count that is not the film's makes `record.mjs` exit non-zero, and a failed render fails the candidate and so the release train. A file reached from `film/` through imports, however indirectly, goes in `film/inputs.sh` (a test follows them transitively). The workflow has two jobs: `render` is read-only (`contents: read`, no credential left in `.git/config`) and uploads the films (`film/out/*.webp`) as an artifact; `publish` holds `contents: write`, only downloads it and runs `film/publish.sh`, and only on `main` (a manual run of another ref renders it, to check, and does not publish). The candidate is built from the head of `main` and the Monday train requires that head, so the released film is always rendered from the released sources. A manual run always renders: `gh workflow run film.yml`. To publish by hand, `film/publish.sh` from the repository root after a render (no argument: every `film/out/*.webp`; or name the files).
10. **The concept films (`deployment`, `plugins`) draw concepts, not terminal output (D2068).** They share `src/parts.ts`: the four components with their colour, name and role (always shown together), the kicker and caption of a scene, the one-command chip on the bottom line, a status pill and the end card. A scene shows at most one real command; elements fade in without rising, one group after another, and a line draws itself from its start to its end once both of its boxes are on screen, so a line always meets the edge of its box.

## The plugins film

A ~37 s silent film (30 fps, no WebGL, 8 MiB cap), "Extend Cartographer with plugins.": what a plugin is (a folder or a git repository, its manifest and one folder per side, each wired to its component); one example plugin for a company (`acme-tools`) with what it adds to each component; then one shot that stays on screen while its state changes: the source and the preview of `plugin install` ("pending approval"), `plugin approve` ("approved"), and one byte of a script changed so its digest turns red and the plugin stops. The sides and what they hold follow `docs/plugins.md` §Contribution points: read it when it changes. Stills: `node film/record.mjs --film plugins --stills 7,15,20,26,32`.

## The deployment film

A ~45 s silent film (30 fps, no WebGL, 8 MiB cap), "Deploy what you need.": the four components with their role, then four scenarios, each drawn as the machines it uses and the components on each: all-in-one (everyone with their own installation, row 1), client and server (many people, one server on a VM or in Kubernetes, rows 3 and 5), no client (any MCP agent on `/mcp/routed`, row 16), and all together (one KB, a git repository on its own, cloned by a laptop, a cluster and a VM, with people and agents on each, row 9). `PROFILES` in `src/deployment.ts` names each row number and the start of its Scenario cell, and `TestFilmDeploymentProfilesAreScenarioRows` (`internal/repodocs`) fails when `docs/deployment.md` renumbers or renames the row. Stills: `node film/record.mjs --film deployment --stills 5,12,20,27,36`.
