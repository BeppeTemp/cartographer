# D1925 — A bug report is redacted by a deterministic leaf package, not by the model

**Decision.** `internal/feedback` redacts a report draft and builds the URL that files it; it uses `internal/secretscan`, the potential-secret detector that `lint`'s `potential_secret` check (D1202) shares. Both are leaves that Compass and Meridian can link (listed as client packages in `internal/boundaries`). `Redact` removes, in a fixed order, secrets and token-shaped strings, URLs and hosts, paths, the account name, concept IDs and KB names, from the `Known` values the caller passes; it is deterministic and idempotent and returns counts per class, never values. `Destination` parses the three modes of a future `feedback.destination` setting (`github`, an `https://` template with `{kind}`, `{title}`, `{body}`, `off`) and `SubmitURL` builds the prefilled URL, carrying the title only past 6000 characters.

**Why.** The repository is public (D259) and the bundled `cartographer-feedback` skill relies on the model to replace real names: one missed host or concept ID is a leak. The code can enumerate what it knows and fail closed where the model cannot. The detector lives in a leaf because a client package may not import `lint` (it reaches `kb`); a new token format is one row in `secretscan` for both users. The cost is heuristics that over-redact (any 32+ character run with letters and digits, any `key=`/`token=` style value, any IPv4 address): a false positive shows as one `[removed]` the user sees, a false negative is a leak. The known over-redactions are accepted: a four-part version such as `0.28.1.2` reads as an address, a UUID or a git SHA is a long run of letters and digits, and a `password:`, `token:` or `api_key=` style key loses its value (after `password`, `passwd` or `secret` the rest of the line). Host names fail closed: any dotted name of two or more labels (letters, digits, `_`, `-`) whose last label is alphabetic is a placeholder host, unless the last label is on a short list of file extensions (`go`, `md`, `yaml`, `sh`...) or the name is `github.com` or the project pages host. A real host with such an ending (`.sh`, `.py`) leaks, and a sentence glued to the next one (`end.Next`) is redacted; an e-mail address becomes `user@example.com` and an scp-style remote `user@example.com:path`. A report URL keeps only an authority that is exactly the project host (no userinfo, no port).

**Alternatives rejected.** Model-only redaction (the status quo): it cannot be tested and fails open. Importing `lint` from the client: it breaks the import firewall. A second copy of the patterns in `feedback`: two lists drift, and the next vendor format would be added to one. An allow-all, deny-some pass ("keep text unless known bad"): replaced by explicit lists of classes and key names.

**Consequences.** The user always reads the whole draft before submitting it; the redactor narrows what that read has to catch and does not replace it (values split across lines are out of scope). The home and workspace paths are also matched in the forms an agent client or a log glues them into: dash- or underscore-joined folder names (`-Users-alice-work-app`, `C--Users-...`), percent-encoded and JSON-escaped paths; the account name is delimited by anything that is not a letter or a digit (`alice-kb` becomes `user-kb`, over-redaction failing closed) and a Windows `DOMAIN\name` is redacted by its name part. `secretscan.Find` returns byte spans and is the only place token formats live; `lint` reports kind and line from it and must never echo the span. `Redact` must stay idempotent and must treat an unknown shape as a reason to remove, never to keep. The placeholders it emits (`example.com`, `$HOME/project`, `area/page-N`, `kb-a`, `user`) are the same ones the skill uses, so a draft redacted twice reads the same. Later changes of the series extend this file.

**The operator's switch (`feedback.destination`).** A server setting (YAML, `CARTOGRAPHER_FEEDBACK_DESTINATION`, restart) with three modes: `github` (the default; a missing field means `github` everywhere, so an older client or server degrades to today's behaviour), `off`, or an `https://` URL template. It is validated at load by `feedback.ParseDestination` (an explicit allow-list of placeholders, a literal host, no userinfo, `http://` only to loopback) and an invalid value refuses the start with an error that names the key and never echoes the template. The server only reports it: `kb_status` (authenticated) carries `{destination, url_template}`, `sync_pull` carries the bare mode and only when it is not `github`; `/health` carries nothing, because a custom template is an internal URL. The server never sends a report.

**Two offer channels.** The managed block is client-written, so the mode reaches it through `sync_pull` into `ApplyOptions.FeedbackMode` and the shared operational section; the section's text is already folded into the block's client-owned hash (the #1502 rule), so changing the setting rewrites each block once on the next `sync` and `status` shows no drift. A generic connection's guide (`initialize` without a block, `kb_guide`) is rendered by the server with the same bullet. A provisioned connection's `initialize` (`entryInstructions`, byte-budgeted by D1724) is unchanged. The bullet is one line (`contract.FeedbackBullet`); `off` emits nothing and the `custom` variant says the report goes to the operator's tracker. Its size raised the shared-section and guide budgets deliberately.

**The internal-error hint.** `Server.internalError` is the single constructor of the two internal-error results (the recovered panic and a handler's Go error, D1516) and appends a fixed sentence to the same text block (a second block would break `client.Call`); `off` omits it. No user-level refusal carries it. The sentence holds nothing from the tool, its arguments or the error, so it cannot leak across scopes.

**Alternatives rejected (this part).** Putting the destination on `/health` (unauthenticated). A hint on every error (noise on refusals the agent is meant to handle). Sending the mode through `initialize` for a provisioned client (breaks D1724's budget and adds nothing the block does not give). A free-text operator message in the instructions (text crossing scopes).

**The template carries no secret.** `kb_status` returns the custom template to every authenticated principal, including read-only and per-KB tokens, so `ParseDestination` refuses at load a query key with a word that is `token`, `key`, `apikey`, `secret`, `password`, `passwd`, `auth`, `authorization`, `sig`, `signature` or `credential` (words split on non-alphanumerics and camelCase, case-insensitive: a substring match refused `assignee_ids`) and any value the secret detector recognises; the error names the key, never the value. An operator who needs an authenticated tracker puts the credential in the browser session of the person who submits, not in the template. The feedback mode on a client is selected per projection from the KBs it reads, so a KB whose pull failed never downgrades another projection's block.

**The command and the skill (1.1).** `cartographer feedback` is the redactor an agent with a shell calls instead of redacting by hand: it reads the draft from stdin or `--file`, learns the installation's names (client config, `/health`, `kb_status`, `concept_list`), runs `feedback.Redact` on the title and the body, appends `feedback.ContextBlock` and prints the draft with the link the destination builds; the draft shown is the one the link carries. It sends and writes nothing. Exit 3 is the operator's `off`. The skill goes to 1.1: it names the moments, calls the command through a single-quoted heredoc and keeps the model pass and the user's approval last; without a shell the by-hand table and URL shapes remain, and a custom destination gets no hand-built link. Alternatives rejected: the command opening the browser or sending (the invariant is that nothing is sent), reading the server through the stdio bridge (a feedback run needs `/health`'s KB list, which the bridge does not expose).
