# D1711 — A client variant reaches Cartographer in one of three declared MCP modes, none of them a script

**Decision.** `mcp.mode` of a variant is `file` (the base's emitter into the variant's own MCP file), `cli` (no entry; the bundled `cartographer-cli` skill and a sentence in the instructions block tell the agent to run `cartographer call --provider <name>`) or `seed` (Cartographer's entry is merged into a plaintext template an editor extension re-seeds its settings from). `seed` (`configurator.SeedMCP`) resolves `template_glob` and `derived_glob` against the home (one `*` segment, symlinked entries are not matches, `safewrite.CheckPath` per match), merges **only** the stdio-bridge entry into each template that holds a JSON object (a template that is not one is skipped with a warning and never touched), rewrites a template only when the entry is missing or different and, **if and only if** a template was rewritten in this run, removes the files matching `derived_glob` (a regular file each, at most three matches, else none) and prints one warning naming them: servers added through the extension's UI are dropped when it next starts. `disconnect` removes the entry from the templates and never the derived file. The seeded entry is always the bridge: it starts with no roots and cwd `/`, so it is read-only until the folder is bound or `unbound_access` says `write` for the variant (printed after the seed). The server includes the bundled `cartographer-cli` skill in a manifest whenever a served KB declares a `cli` variant (`BuildManifest`), the client filter keeping it from every other provider.

**Why.** Three clients need three things: a settings file Cartographer owns, no tool surface at all, or a file a vendor overwrites from a template at every start. The derived store is what the extension actually reads, and it is rebuilt from the template only when it is gone, so seeding the template without resetting it changes nothing; resetting it on every sync would drop the user's own servers every time, hence "only after a template changed" and a hard cap on what may be deleted. The server cannot know which client asks for a manifest, so it lists the skill for a KB that declares the mode and leaves the narrowing to the client filter that already exists.

**Alternatives rejected.** A script field in the descriptor (code from a KB run on the user's machine: the descriptor is data, approved by hash). Seeding the derived file directly (encrypted, owned by the extension). Resetting the derived file on disconnect too (destroys the user's own servers; the message says to remove the server from the extension's UI). Passing the client's provider to `sync_pull` so the server narrows the skill (changes a wire contract for a one-line filter that exists).

**Consequences.** A `seed` variant needs a JSON base and a template glob (`RegisterVariant` refuses otherwise); KB `mcp` artifacts are unsupported for it. The cap on derived files and the "restart the window" warning are part of the contract and tested. `mcp.allow_call` stays refused for `cli` until the permission rule is probed.
