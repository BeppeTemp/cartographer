# D2294 — A flaky Go test leaves the gate's verdict by a versioned line with an issue and an expiry, and lapses back into it

**Decision.** A known-flaky Go test is taken out of the verdict by one line of `test/quarantine.tsv`: its package's import path, its top-level test function, the issue that tracks the fix, the day it was added and an expiry. `scripts/quarantine.sh` reads the list and turns its active entries into a `go test -skip '^(A|B)$'`, which `make test`, `make race`, `make test-rerun` and `make check-run` add to every `go test` they run, saying how many tests they skipped. `scripts/test-shard.sh` (the Windows shards of `ci.yml`, `hosted-check.yml` and `ready-check.yml`, and the build host's Windows leg, its targeted retry and the lander's probe of a Windows failure) drops those names from their package's plan instead, and says so too. An entry is active through its expiry day, in UTC. After that it lapses: nothing fails, the test is back in the verdict without any change to the list, and the `quarantine` job of `ci.yml` says so once on the entry's issue. The same job runs every active entry on each push to `main`, outside every verdict, and its summary says which passed. The script refuses an entry whose package or test name is one of `internal/repodocs`, which holds the documentation and process pins, the list's own checks among them. The clock is replaced only by a `--today` option the tests pass, never by the environment. The list is static-checked by `internal/repodocs`: every entry has an issue and an expiry at most 30 days after it was added, and names a test that exists in its package and is unique in the module. A list that does not parse fails every caller.

**Why.** Forty-seven flaky-test issues were opened in three weeks. Each flake was found again by every train that tripped on it, at the cost of one targeted retry or one whole re-run of the gate per occurrence, until somebody fixed it. The issue already says the test is flaky, and the retry learns nothing new the second time. Naming the test once, with a bound, takes it out of the train's path. The expiry and the issue make quarantine a loan, not a place to park tests: the issue stays open, and the test comes back on a date nobody has to remember. It costs a quarantined test's coverage while it is out. A regression it would have caught in that window reaches `main` unseen, except in the `quarantine` job's summary.

**Alternatives rejected.**
- A helper that each flaky test calls to skip itself: the quarantine would be spread over the code, with no single list to review, count or expire, and taking a test out would mean changing the test.
- A `repodocs` test that fails on an expired entry: every gate, and every `make check`, would turn red on a calendar day with no change queued. Lapsing applies the same pressure without failing on a date.
- Keeping only the retry (D1755) and the flaky issue: this is what produced the repeated retries above.
- Quarantining vitest, Playwright or e2e tests the same way: they stay under the existing rule (fixed at the cause or deleted). Only `go test` has a `-skip` that every call site can share.
- Passing the skip through `SIGNOFF_WINDOWS` to the build host's Windows retry and probe: it would send a regular expression through a wrapper that may re-parse its arguments in a remote shell, which D1755 rules out. They call `scripts/test-shard.sh` over the packages' import paths instead, as the leg does, so only plain words cross the wrapper and the names are dropped on the far side.
- A clock override read from the environment (`QUARANTINE_TODAY`): every caller would inherit it, and an exported past date would keep lapsed entries out of a local or build-host gate. It is a `--today` option that only the tests pass.
- Leaving `internal/repodocs` to the static check alone: one `-skip` applies to every package, so an entry naming the static check itself would switch it off with the rest of the documentation pins, and the gate would stay green.

**Consequences.**
- `-skip` matches a name in every package of the call, so one expression over `./...` is exact only while each quarantined name is unique in the module. The static check enforces this, and a quarantined name can block a new test of the same name elsewhere until its line is gone.
- A new `go test` call site in the `Makefile`, `scripts/` or a workflow must add the skip or be exempted by name (`internal/repodocs/quarantine_test.go` fails otherwise).
- `$(shell)` loses an exit code under make 3.81, so the `Makefile` validates the list again in each of the four targets before its `go test`.
- The lander's flaky issues say how to quarantine the test. Quarantine is not a fix, and a rerun that turns a flaky test green is still not one.
- Amends D1755: the targeted retry stays for the build-host gate, and a flaky test that has been named is quarantined rather than retried train after train. The Linux retry (`make test-rerun`) is unchanged and carries the skip like every make target; the Windows retry and the lander's probe of a Windows failure now call `scripts/test-shard.sh` instead of `go test` over the packages.
