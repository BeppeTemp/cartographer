# D2409 — The created-files ledger records the provider roots Cartographer created

**Decision.** The created-files ledger (`.cartographer-created.json`, D1269) gains a `dirs` list beside `files`: the provisioning root directories (`.claude`, `.codex`, `.config/opencode`, `.github`, ...) that Cartographer itself created, as slash paths relative to the base dir. Only the boundary set is recordable, and the set (`rootDirs`) now lives in `internal/configurator` next to the ledger, readable through `IsRootDir` and `RootDirs`. The ledger file goes with its last entry of either kind.

**Why.** After `workspace unbind` + `sync` or `disconnect` the roots Cartographer created stayed behind empty, because `pruneEmptyDirs` cannot tell an emptied root from the user's own (D63 point 1: roots are never removed). Nothing recorded which directories were ours. A record of the directories we created, kept where the files we created are already recorded, is what a later prune needs to remove only those. The set moves down to the configurator because `provisioning` imports it and the contract package imports it, never the reverse.

**Alternatives rejected.**
- Record every directory the writers create: the levels under a root already follow D63 (removed when empty, whoever made them), and a ledger applied to them would stop removing, after an upgrade, levels a `disconnect` removes today.
- Keep the set in `provisioning` and pass it to the ledger: the configurator cannot import provisioning, and the ledger must validate what it reads.
- Trust the ledger as read: it is untrusted input like the lockfile; an entry that is empty, absolute, contains `..` or is not a root is dropped on read, so a hand-edited ledger cannot name `$HOME` or `.ssh`.

**Consequences.** The ledger API is `NoteCreatedDirs`, `WasDirCreated`, `ForgetCreatedDir`, `ReconcileCreatedDirs`. "Created" is decided where the directory is made: `safewrite.MkdirAllNoFollowCreated` makes each missing component with `os.Mkdir` after the symlink walk and lists only those it made itself, so a component that existed, or that another process made first, is never recorded. The provisioning wrapper and the configurator's MCP directory write record the roots among them; Cline's Documents folder and `.git/info` are outside the root set, so they record nothing. A root first made by `blocktext`, by `TrustCodexProject` or by a plugin provider's MCP file is not recorded (accepted gaps). A failure to record is ignored: the directory stays unknown. Removal happens only as the tail of our own prune: `pruneEmptyDirs` reaches a root after removing a managed file below it, asks the ledger, re-checks the boundary, refuses links, removes it with `safewrite.RemoveEmptyDir` and confirms by `Lstat` that it is gone before it forgets the entry and climbs (`.config/opencode` then `.config`); a non-empty root, a link or any error stops the climb and keeps the entry. It returns the roots it removed and every caller surfaces them (`AppliedResult.PrunedRoots`, `PruneReport.RemovedRoots`). `Apply` and `PruneManaged` first forget entries whose directory is no longer a directory. `disconnect` gets the same behaviour. Every removed root is announced, one line per root (`printPrunedRoots`: sync, both prunes of `disconnect`, `workspace unbind` + `sync`, plugin removal), and a dry run predicts the roots by name (`RootPredictor`), a read-only walk with the same boundary and ledger predicates as the real climb: nothing is copied or written (a scratch copy of the roots was rejected: it copied credentials into the temp dir, was unbounded and did not see a symlinked parent the real run refuses). The set of files the run deletes is the managed files plus, for the prunes that strip shared files, the shared files the removal deletes once nothing else is in them, accumulated across the providers of a `disconnect` in real-run order so a shared root is predicted where it goes; `sync --dry-run` counts managed files only and can list fewer roots. A shared file the user also keeps entries in makes the prediction list a root the real run keeps, so the output is a prediction; an unreadable recorded root is reported as unknown. The configurator never removes a root when it deletes an emptied MCP config file (it climbs one level, never into a root): `PruneConfigFileParents` removes a recorded one after it and returns it for the announcement, only when that disconnect deleted the file (a directory that was already empty is the user's); `connect` and `sync` reach the same removal for a stale entry without it, so a root they leave empty stays until the next `disconnect`. A root deleted and recreated empty between two syncs is indistinguishable from the one we made (the ledger holds no identity): accepted, bounded to a root the user emptied themselves and that a prune of ours then empties again. A directory absent from the ledger is unknown and is never removed. An older client rewrites the ledger from its `files` map and drops `dirs`, which only makes the directories unknown again. Adding a root means adding it to `rootDirs`, with `TestEveryDestinationRootIsAPruneBoundary` as the net.
