# D2398 — A page links a page of another mounted KB with `[[kb:<name>/<id>]]`, and the link is checked per caller

**Decision.** `[[kb:<name>/<id>]]` (the mount name or an alias; the grammar reserves `@<server>`, parsed and resolved nowhere) names a page of another KB mounted on the same server. Resolution reads the other KB's graph snapshot only, never its git lock. A caller is told one of four states: `resolved`, `missing` (only a caller who reads the target KB whole), `unresolved` (one neutral value for an absent, unmounted, unreadable or `@server` target) and `out_of_scope` (a reader of a KB the connection does not bind, with the bind text of the connection kind, D1101). `broken_cross_kb_link` blocks a write like `broken_link`; a finding that names another KB (`Finding.OtherKBs`) is shown only to a caller who reads that KB whole (`crossReadable`), and the cached lint stays caller-agnostic and is filtered per caller after the cache. A link that names the writer's own KB is a finding with the fix `[[<id>]]`, never an edge. A resolved cross edge, incoming or outgoing, clears `orphan` only for a caller who reads that KB whole: the shared lint keeps the finding and names the clearing KBs in `Finding.ClearedBy`, so the verdict is no existence oracle; the lint cache key moves with the other KBs' targets and inbound links (`crossStamp`).

**Why.** A reference to another KB was backtick text, so nothing checked it and a page whose only links were cross-KB was refused as an orphan. A link that dangles would make `orphan` and backlinks lie, so it blocks; but a writer who cannot read the target must neither be blocked by it nor learn it is missing, so the one neutral outcome and the per-caller filter carry the whole disclosure rule, and the cache stays shared.

**Alternatives rejected.** A markdown `kb:` href as a second form: one syntax is enough and an href is read by viewers that would show it broken. Resolving a self-named link against the own KB: two spellings of one link; the finding with its fix keeps one. Cross edges inside the in-KB adjacency: PageRank, `graph_context` and `search` would then leak them to a caller who cannot read the other KB. A fingerprint per caller in the lint cache: it multiplies the cache by the number of rights.

**Consequences.** The syntax is unusable on servers 0.29.0 and 0.29.1, which refuse a page holding such a link (`broken_link` at the write gate); from 0.29.2 a target starting with `kb:` is never an internal link. Every surface that names a KB goes through `crossFindingVisible` (the line in `internal/mcpserver/AGENTS.md`); a new one extends the leak test. Moving or renaming a target is not rewritten: it becomes `broken_cross_kb_link`, or `unresolved` for a caller who cannot read the KB.
