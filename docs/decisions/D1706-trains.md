# D1706 — A maintainer's changes land in trains: queued as one commit each, gated once per train

**Decision.** A maintainer's finished, reviewed change is queued with `make ready` as one commit on `refs/heads/ready/<slug>`, its message the changelog entry (checked by `scripts/commit-lint.sh` as `pr-title` checks a PR, and by the size cap as `plan-gate` does). The lander (`scripts/land.sh`, started by `make ready`, exiting when nothing is landable) cherry-picks up to 8 queued changes onto `main` in queue order (`Lander-After:` before, `Lander-Hold:` and the freeze keep a change queued), gates the train once with `scripts/signoff.sh`, and opens one PR `chore(dev): train <id>, <k> change(s)` that auto-merge **rebase-merges**, so each change is its own conventional commit on `main`. A red train is gated again (green then: a flaky test, which lands and gets a `bug` issue); red twice, bisection over the prefixes rejects the first breaking change to `refs/heads/failed/<slug>` and lands the green prefix. A maintainer's decision is written as `docs/decisions/D-new-<slug>.md`, cited as `D-new-<slug>`, and numbered by the lander above both the highest decision and the newest issue or PR number, in the change's own files. A contributor's PR is unchanged: CI tests it, it is squash-merged, its decision takes its PR number (D672).

**Why.** Measured over 85 maintainer PRs (#1600–#1703): 167 signoff pushes, about two full gates per PR on a build host that runs one at a time, because review came after the signoff and the D672 renumbering after the PR number was known forced a second one. 51 of the 85 merged on a base that `main` had already moved past, with no Linux break: per-PR gating bought nothing a later gate of the combined tree would not. The GitHub part after the signoff took a median 1.6 minutes; the wait was the gate queue, the polling (about 200 status calls) and the rules that kept PRs few (at most 4 open, none dependent on another), which serialised independent work. A train pays one gate for k changes, takes the PR number out of the change (so nothing is renumbered after the gate), and lets dependent changes queue in order. It costs the per-change CI record (the train has one `signoff` status), a bisection of up to log2(8) extra gates when a train is red, and a lander process on the maintainer's machine.

**Alternatives rejected.**
- GitHub's merge queue: offered only to repositories owned by an organization, and it runs CI's gate per group, which the signoff replaces with the build host.
- One PR per change, merged by the lander in batches: the same gate per train, but k PR round-trips and k `signoff` statuses to post on heads that change on every rebase.
- Squash-merging the train PR, its changes as body lines: the changelog survives, but a change is no longer one commit to revert or bisect on `main`.
- Stacked PRs: dependent changes in order, still one gate each.
- Numbering a decision after the train PR: a train can carry several decisions; the train PR number is known only once the gate is green.
- The lander on a hosted runner: the gate needs the build host and the maintainer's signoff identity; the hosted CI is already the fallback when the host is away (exit 75, D1704).

**Consequences.** `main`'s ruleset allows rebase merges (train PRs) beside squash merges (every other PR). `main` never holds a `D-new-*` file: a change citing a placeholder that is neither on `main` nor added earlier in its train is rejected. One train is open at a time across machines (an open PR whose head is `train/*` makes another lander wait), one lander runs per machine (a pid file in its state directory). A change leaves the queue only by landing or by moving to `failed/<slug>`, whose last commit message is the reason; queuing it again replaces it. A gate that fails for a reason that is not a test stops the lander and leaves the queue untouched. Amends D672 (maintainer decisions are numbered on landing, not after the PR) and D1610 (the signoff attests a train, not each change).
