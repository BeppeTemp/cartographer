# D1728 — Approvals and opt-outs live in a fail-closed machine file

**Decision.** The local approvals of hooks, executable artifacts and MCP descriptors, the `approvals_migrated` marker and the operator's opt-outs (`sync_timer_opt_out`, `tray_opt_out`) are kept in `.cartographer-machine.json`, next to `.cartographer.yaml` and the state file. The name follows the content: it holds more than approvals. `approvals_migrated: true` also stays in `.cartographer.yaml` as a tombstone, and the two opt-outs are still copied into the state file. An unreadable machine file fails closed: `Load` approves nothing, sets the migration marker so a sync does not approve what is installed in its place, and warns that the file is unreadable; `Save` leaves the file and the old YAML keys as they are, and refuses a command that would record an approval, or change an opt-out against the state copy. A missing machine file after the migration (tombstone set, `mcp_approvals` gone from the YAML) is the same: nothing approved, nothing migrated, and a warning to give the approvals again with `cartographer approve`.

**Why.** `mcp_approvals` and `approvals_migrated` are written by commands and "do not edit by hand", yet they sat in the file people edit, and the opt-outs sat in the state file. The state file is a cache tolerated when corrupt or missing; for an approval, treating a corrupt file as empty is safe but treating the marker as lost would re-approve installed hooks and bring a revoked approval back. A separate file whose only failure mode is "approve nothing, say so" removes that class of defect, and leaves the state file a plain cache (plus the connected agents).

**Alternatives rejected.** Keeping them in the YAML: a hand edit or a failed parse can silently drop the consent. Keeping them in the state file: its contract is "absent or corrupt is rebuilt". Leaving the opt-outs in the state file: they are operator choices no sync rebuilds, the same nature as the approvals. A file named `approvals`: it would hold more than approvals.

**Consequences.** The first `Save` (or `client realign`) over a machine that still has the old keys writes the machine file, then drops `mcp_approvals` and `sync_timer_opt_out` from the YAML, after keeping `.cartographer.yaml.bak-pre-machine` (never overwritten; restoring it, with the machine file removed, returns to the old layout). While the machine file is absent and the YAML still holds `mcp_approvals`, `Load` reads the old homes; once the file exists they are ignored, so a stale copy on a read-only mount cannot bring an approval back. Downgrade: an older client sees `approvals_migrated: true` and no approvals, so it asks for each approval again and never re-approves what is installed; it sees the opt-outs in the state file. The state-file copy of the opt-outs is written for this minor only and stops in the next one, when the older clients are out of support; from then on only the machine file holds them. A future key of this kind (written by a command, never edited, not rebuildable) goes here.
