# D2053 — The documentation is a generated knowledge base: small units, a hub per page, decisions as leaves

**Decision.** `internal/docskb` turns the repository's own markdown (`README.md`, `CONTRIBUTING.md`, `docs/*.md`, `docs/brand/*.md` and `docs/decisions/*.md`) into an OKF knowledge base named `cartographer-docs`. The generator is a pure function of those files and of a git ref: no model, no Surveyor, no clock, so the same input gives the same bytes (a test generates twice and compares).

The shape follows what `search` and `graph_context` reward:

- Three maps under `data/`, taken from the two tables of `docs/index.md` and from the decisions: `using-cartographer/`, `internals-contributing/` and `decisions/`. A page file in no table is a generator error. The root presentation (`README.md`) and the contribution guide (`CONTRIBUTING.md`) are a declared, ordered input list of the generator, not a special case, and `docs/index.md` is the page `internals-contributing/docs-map` with its two tables replaced by the map indexes.
- A page is an expanded concept (`map/page/index.md`) whose sections are its satellites (`map/page/section`, the deepest id the data plane allows). Its index lists every section, sub-sections indented, so the curated-index check holds by construction.
- A section is the H2 unit; while it exceeds 8 KiB and has deeper headings it is split at the next level, then the next; a leaf still above 16 KiB is cut at blank lines outside fences and tables into parts of at most 8 KiB, each linking its neighbours. Headings are found by a fence-aware line scanner (a `#` in a fenced block is no heading); no markdown dependency is added.
- A unit's title is its heading path joined by " — ", page title first, and its body starts with that same string as its H1. Slugs are the ASCII, lowercased heading path, de-duplicated with `-2`, `-3`; the GitHub anchor of each heading is kept separately for anchor resolution and for the pinned `source_url`.
- A decision is one leaf concept (`decisions/d193-…`, the file stem lowercased), never split, its body verbatim minus the YAML frontmatter, grouped by topic in `repodocs.TopicOrder` in the map index. `TEMPLATE.md` and pending `D-new-*` files are left out, and so is the generated decisions list block of `docs/decisions.md`.
- Every generated concept carries `provenance` (the repository path), `source_url` and `origin: external`: its text is a verbatim copy of a repository file, which is what that marker says to the machine-path, open-marker and title-length checks. No `timestamp`, so there is no decay finding and no nondeterminism.

The units, not the pages, are the retrieval unit: a hit whose title and first lines say what it answers is the answer. The rest of the plan builds on this model: links rewritten to wikilinks and pinned URLs with the lint gate (next change), the embed of the docs in the binary, `cartographer docs` running the real read tools in-process over a private per-invocation materialization in a temporary directory (not in memory, because the read paths work on directories and write per-KB state; not a shared cache, because two concurrent invocations would race on that state), the retrieval eval, the `cartographer-docs` skill and the hosted demo serving the KB beside the astronomy one. The embed is one module-root Go file so the root pages come in; it adds about 3.6 MB to the binary, stored raw.

This supersedes the guestbook of D800 (the demo serves the documentation KB instead); the static Atlas's live source of D800 stands.

The demo image (`deploy/demo/Dockerfile`) bakes both KBs in: astronomy replayed as before, and `cartographer-docs`, written at build time by the base image's own `cartographer docs export` and sealed by one commit with a placeholder identity, so the docs are those of the binary that serves them. The guestbook seed (`demo/guestbook/`), the image entrypoint that cloned it and its smoke steps are deleted; `CARTOGRAPHER_DATA` stays, pointing at an empty writable directory, because a folder session has no credentials directory and the audit log would run unsigned. Since nothing external is cloned, the `demo` workflow's post-deploy check that the documentation KB answers is an error, no longer a warning (the reason of D800 for a warning is gone); dispatching the workflow on a tag that predates `docs export` fails the image build.

**Links.** Relative `.md` links and `#anchors` of a page become `[[id|label]]` wikilinks (root-relative ids are base independent); an anchor resolves to the unit that holds the heading, even one inside a section that was not split, and an anchor with no heading is a generator error naming file and line. Any other link into the repository (code, `docs/openapi.json`, `docs/schemas/`, a directory, an image) becomes the pinned GitHub URL (`blob`, `tree` for a trailing slash) at the version tag when the build's version is exactly `vX.Y.Z` or `vX.Y.Z-rc.N`, else `main`; external URLs are untouched; code spans and fenced blocks are not scanned and a title after a destination is dropped. A second link to the same target in one paragraph is written as its label, which keeps `repeated_link` quiet. Every `D<n>` in the prose of a unit that has a decision file ends up in one appended line, `Decisions cited: [[decisions/d<n>-…|D<n>]], …` (ascending, at most 12, not the decision itself, not one the unit already links), which gives `graph_context` the why-trail and leaves decisions as leaves.

Three rules keep the lint clean without touching a page. Wiki-link syntax shown in prose (`[[a]]`) is put in a code span. The `{{repo:…}}`/`{{path:…}}` placeholders the docs cite as examples are declared in a generated `paths.yaml`. The generated decisions list of `docs/decisions.md` is replaced by the decisions map, whose ten topics are concepts (`decisions/topic-<slug>`, type `DecisionTopic`) that list their decisions: the `#topic` anchors of the dropped list resolve to them, and each decision ends with a `Topic:` link, so no decision is an orphan. `internal/docskb` generates the KB from the real docs in `go test` and fails on any lint finding but the four about the docs' own prose.

**Embed and runner.** The embed is `docsfs.go` at the module root (package `cartographer`, `//go:embed README.md CONTRIBUTING.md docs/*.md docs/brand/*.md docs/decisions/*.md`), stored raw (about 3.6 MB; compressing needs a generated artifact the release tooling does not have). `GO_DIRS` of the Makefile names the file so `fmt` and `fmt-check` cover it without gofmt walking `web/` or `demo/`. A test generates the KB from the embedded files and from the disk and compares every byte, so a docs subdirectory the patterns miss fails it. `Export` writes the tree into an empty or missing directory and refuses any other. The runner materializes the tree once per instance in `os.MkdirTemp` (removed by `Close`; leftovers older than 24 h are swept by age), opens it with `kb.Open` and serves it through the real routed read-min mount (`/mcp/routed?access=read-min`) driven in-process with a per-process token scoped `kb:cartographer-docs:r`: the profile, schemas and refusals are those of D1184 and a write is refused `read_only_profile`. Measured cold start (generate, write about 1.3k files, open, first search): about 0.65 s on the Linux test host, and about 1.06 s (`BenchmarkRunnerCold`, 10 runs) on a native Windows desktop with a local SSD. That is above the 1 s the plan asked for, and a hosted Windows runner is several times slower again (file creation dominates): the package tests take 245-385 s there against 35 s on Linux when each test builds its own runner. The design is unchanged; the tests share one runner per test binary and keep one real per-invocation path (`TestDocsWritesOnlyItsTempDir`), so the cost is paid once by the tests, but a user on Windows pays about a second per `cartographer docs` call.

**Command.** `cartographer docs` (Get started group) reuses the `call` UX through a small `callTransport` interface that the bridge session and the in-process runner both satisfy; the runner exposes `Raw` (the whole JSON-RPC response) so an argument error keeps its exit class 1. It is the one reader that writes: a private temp directory per invocation, removed on exit, so its test (`TestDocsWritesOnlyItsTempDir`) is weaker than `TestCallWritesNothing`: nothing is left in `$HOME`, the working directory or `$TMPDIR`, and a read-only `$HOME` works. The binary now imports `docskb`, so it leaves the `not_in_binary` list of `scripts/ci-filters.sh`.

**Why.** An agent asked how workspace binding works could not answer: the answer is in `docs/configurator.md` and `docs/sync.md`, which an agent cannot consult. More skill prose would drift from the docs; a KB that is a function of the docs cannot. Small units make `search` precise and `graph_context` cheap, and the page hub plus the `Part of` line put the neighbouring sections one hop from a hit.

**The eval (D9).** `TestRetrievalEval` asks the real read tools the 76 questions of `internal/docskb/testdata/questions.jsonl` over the KB generated from the real docs: at least two per page of `docs/index.md`, `README.md` and `CONTRIBUTING.md`, at least twelve whose answer is a decision. k is 5 ranked `graph_context` results after its seeds (the seeds are the top five search hits and the results exclude them, so the union is what an agent sees) and 10 `search` hits: the skill reads at most five sections, and a hit below the tenth is not found by an agent that reads snippets. A question is searched with its content words (question words dropped), because the index matches whole words, ANDs them and falls back to an OR in which `how` and `does` outweigh the topic. A failing question is fixed in the docs wording, never in the generator or the test; the first run failed 47 of 76, and what remained after rephrasing the questions into the words the pages use was fixed by a lead sentence under nine headings. The per-topic decision hubs crowd `graph_context` (two to three of its five ranked slots in the failing runs) and do not change `search`; without them one question flips, so the eval does not tell them apart and they stay.

**Alternatives rejected.**
- Generation by a model or the Surveyor: not reproducible, costs a provider, and drifts silently.
- Compressing the embedded docs: needs a generated artifact (committed, or a pre-build step the release tooling does not have).
- One concept per page: a 200 KB page is not a search hit.
- H2 units only: five H2 sections of the real docs exceed 90 KB each.
- A shared cache directory for the materialization: concurrent invocations race on the per-KB state files the read tools write.

**Consequences.** A docs page in no table of `docs/index.md` fails the generator. The size caps (8 KiB and 16 KiB) are variables only so that the tests can lower them; a block no blank line can cut stays whole and is named in the size test. A heading rename changes a concept id. The later changes of the plan complete this record with the link rules, the embed, the runner and the eval.

**Skill and managed block.** The bundled `cartographer-docs` skill routes every question about how Cartographer works to `cartographer docs`: query with the content words of the question (nouns, command and config names), never the whole sentence, because the runtime index matches whole words and a sentence full of filler words missed about 60% of the time in the eval where content-word queries passed every question; then `graph_context` and a whole `concept_read` of the cited sections, an answer that cites concept ids, the `Decisions cited:` line for a why, and the `cartographer-feedback` skill when the docs have a gap. It runs a command, so like `cartographer-ops` it is not served by `kb_guide`. A skill description alone is what a model may or may not pick, so the shared operational section of the managed block gains one bullet with the same routing; each client's block is rewritten once at the next `cartographer sync`, a one-time drift, not an error. `cartographer-ops` becomes 2.0: the mental model, the first-time setup, a diagnosis playbook of one-line steps with a docs query each, Upgrade, Update notices and Never do stay; the command and configuration tables and `references/placeholders.md` go (the docs carry them), and the three agent rules of `references/sync-errors.md` that no doc carries (report, never merge, rebase, push or delete a branch yourself; no retry loop on a protected-branch refusal; `kb reauthor` without `--apply` first) move into the playbook before that file goes.

**Managed-block budgets raised.** The extra bullet is paid on every model call of every client, so the byte budgets that guard the block are raised deliberately, not by accident: the hard cap of the shared operational section in `TestBlock_Budget` goes from 2560 to 2800 bytes (the longest rendering, feedback `custom`, now measures 2681), and the fixed-cost caps of `fixedcost_budget_test.go` go from 3944 to 4096 bytes for one KB and from 8192 to 8448 bytes for nine KBs, past the 8192 of D1246 (measured 3972 and 8324). Nothing else grew: a later bullet needs its own decision.

**Root pages and the site.** `README.md` and `CONTRIBUTING.md` live outside `docs/`, and a Go embed cannot reach a parent directory, so the embed is a file at the module root instead of `docs/docs.go`. That is also why the `docs` workflow and `mkdocs.yml` need no exclusion for it: MkDocs never sees a Go file at the root, and `GO_DIRS` names it so the formatting gates cover it. The two root pages are ordinary concepts of the `using-cartographer` and `internals-contributing` maps.

**The demo Worker and the guestbook.** The Worker keeps only forwarding, the `/mcp` body cap, the 5 s edge cache with CORS, the 404 under `/.well-known/` and the read token; the moderation, the KV namespace, the Workers AI binding, the write token and the guestbook secret are removed with the guestbook. This supersedes the guestbook, its moderation and its write token of D800; the static Atlas's live source that D800 introduced stands, and now shows both KBs. The README's "Try it now" asks Cartographer about itself first and keeps the astronomy atlas as the second tour.

**Release impact.** The binary grows by about 3.6 MB. Every client gets one managed-block rewrite at the next `cartographer sync` and the new bundled skill; `cartographer-ops` 2.0 replaces 1.8. The maintainer runs `terraform apply` in `deploy/demo/` **before** the release that carries this change: it sets the read token's scopes to `kb:astronomy:r;kb:cartographer-docs:r` and destroys the guestbook secret, its version and IAM binding, the KV namespace and the Worker's moderation bindings; until then the `*.run.app` service keeps serving and the `demo` workflow's check on the documentation KB fails. The private guestbook repository and its git token can be retired afterwards, outside this repository. The answer quality of an agent using the skill is checked during the release candidate, not by a test.
